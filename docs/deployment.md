# Deployment behind Coolify / Traefik (maintainer recipe)

> Most people should use [self-hosting.md](self-hosting.md) (installer +
> `dreamward-ctl`) or the [desktop app](desktop.md). This page documents a
> CI-driven deployment next to other apps on a VPS that already runs
> **Coolify** (its Traefik proxy owns ports 80/443) — the way the project's
> own instance runs.

Dreamward runs as a standalone Docker Compose stack at
`/opt/dreamward` (repo variable `DEPLOY_PATH`), routed through Coolify's Traefik via labels — no published
ports, no conflicts with other apps on the host.

## Moving parts

| Piece | Where | Purpose |
| --- | --- | --- |
| `docker-compose.prod.yml` | repo + `/opt/dreamward` (shipped on each deploy) | api, web (Traefik labels), backup sidecar |
| `/opt/dreamward/.env` | VPS only — never in git | domain, secrets, admin credentials |
| `ghcr.io/sufzen/dreamward-{api,web}` | GitHub Container Registry | images built by the Release workflow |
| `.github/workflows/ci.yml` | GitHub Actions | typecheck + build + tests on push/PR |
| `.github/workflows/release.yml` | GitHub Actions | build → push → deploy → health check |

## One-time setup

1. **DNS** — `A life.example.com → <VPS IP>` (use your domain).
2. **VPS bootstrap** — run [`scripts/deploy/setup-vps.sh`](../scripts/deploy/setup-vps.sh)
   as root: creates `/opt/dreamward/.env` with generated `JWT_SECRET` and
   `KEY_ENCRYPTION_SECRET` (0600).
3. **GitHub secrets** — `VPS_HOST`, `VPS_USER`, `VPS_SSH_KEY` (a dedicated
   ed25519 deploy key whose public half is in the VPS `authorized_keys`).
4. **Monitoring** — add `https://<domain>/api/health` to uptime-kuma.

## Releasing (the normal path)

```bash
git tag v0.2.0
git push origin v0.2.0
gh release create v0.2.0 --generate-notes
```

Publishing the release triggers `release.yml`:

1. buildx builds both images and pushes `:v0.2.0` + `:latest` to GHCR.
2. `docker-compose.prod.yml` is scp'd to `/opt/dreamward`.
3. Over SSH: ghcr login (ephemeral `GITHUB_TOKEN`), `TAG` persisted into
   `.env`, `docker compose pull && up -d --remove-orphans`.
4. The workflow curls `https://life.example.com/api/health` until
   healthy (5 min budget) and fails loudly otherwise.

**Rollback:** Actions → *Release & Deploy* → *Run workflow* → enter the
previous tag (e.g. `v0.1.0`). Images are immutable; the database migrates
forward-only (additive), so rolling the app back is safe.

## Traefik integration (how routing works)

Coolify's Traefik runs with `providers.docker` and `exposedByDefault=false` on
the external `coolify` network. The `web` service is dual-homed (`internal` +
`coolify`) and carries labels:

- `Host(\`${DREAMWARD_DOMAIN}\`)` on the `https` entrypoint with
  `certresolver=letsencrypt` (HTTP-01 — port 80 must keep flowing through
  Traefik) and an HSTS middleware;
- an `http` router that 301s to https.

The `api` container sits only on the `internal` network, so nothing is
published on the host.

### SSE (AI chat streaming)

The agent chat streams server-sent events. The chain that keeps it unbuffered:

- Traefik: streams by default (no action needed);
- web nginx: `proxy_buffering off; proxy_cache off; proxy_read_timeout 1h`
  on `/api/` (see `apps/web/nginx.conf`).

If chat ever "answers all at once", check those nginx directives first.

## Server env (`/opt/dreamward/.env`)

| Var | Notes |
| --- | --- |
| `DREAMWARD_DOMAIN` / `PUBLIC_ORIGIN` | domain + `https://` origin (invite links use this) |
| `JWT_SECRET` / `KEY_ENCRYPTION_SECRET` | generated by setup; rotating the latter invalidates stored AI keys |
| `DREAMWARD_EMAIL` / `DREAMWARD_PASSWORD` | optional admin bootstrap (only used while control.db is empty; otherwise the one-time setup link is used) |
| `MAX_USERS` | seat cap (default 10) |
| `ADMIN_OPENROUTER_KEY` | read by the seed-admin-provider script |
| `CODEX_ENABLED` | experimental ChatGPT provider toggle |
| `TAG` | deployed image tag (managed by the workflow) |

## Day-2 operations

```bash
# status / logs
cd /opt/dreamward
docker compose -f docker-compose.prod.yml ps
docker compose -f docker-compose.prod.yml logs -f api

# seed/refresh the admin's OpenRouter provider from ADMIN_OPENROUTER_KEY
docker compose -f docker-compose.prod.yml exec api node dist/scripts/seed-admin-provider.js

# reset any user's password
docker compose -f docker-compose.prod.yml exec api node dist/scripts/reset-password.js user@example.com "new-password"

# manual restart with the pinned tag
docker compose -f docker-compose.prod.yml up -d
```

Migrations run automatically on boot (control DB DDL + per-user Drizzle
migrations on first open). Keep user-DB migrations **additive-only**.

## Local production-like run (no Coolify)

`docker-compose.yml` (the non-prod file) still ships a Caddy-on-443 stack for
a dedicated host: `docker compose up -d --build` with `DREAMWARD_DOMAIN` set.
